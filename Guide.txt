### 1. Overcoming the "I Understand Everything, but Get Stuck When Coding" Hurdle

Getting stuck when staring at a blank file is completely normal at your stage. It happens when you try to think about the **entire system at once** (UI, database, edge cases, error handling, CSS).

Here is the **Senior SDE Mental Framework** you will use on this project:

```
[ Step 1: Data Contract ]   → What data comes in? What data goes out? (Zod schema)
         ↓
[ Step 2: Database Schema ] → What does MongoDB store? What are the indexes?
         ↓
[ Step 3: Pure Core Logic ] → Business rules in isolation (Service layer)
         ↓
[ Step 4: Transport Layer ] → Express Route / Controller + HTTP status codes
         ↓
[ Step 5: Frontend Hook ]   → Fetch data & connect to UI components
```

> **The Golden Rule:** Never write code until you have written the data shape (TypeScript interface or Zod schema) on paper or in a comment. Once the types are clear, the code writes itself. We will tackle every single module using this exact workflow.

### 3. Pragmatic, Time-Optimized 5-Phase Roadmap

To balance your time constraints and build an impressive full-stack portfolio piece, here is how we will stage the work:

```mermaid
flowchart LR
    A[Phase 1: Architecture & Auth] --> B[Phase 2: Product & Inventory Engine]
    B --> C[Phase 3: Unified Order & State Machine]
    C --> D[Phase 4: Customer Storefront & POS UI]
    D --> E[Phase 5: Kitchen KDS, Polish & Deploy]
```

#### **Phase 1: Architecture, DB Foundation & RBAC Auth**
* Clean 3-tier backend architecture: `controllers/`, `services/`, `models/`, `middlewares/`, `validators/`.
* JWT in HTTP-only cookies + Role-Based Access Control (`Customer`, `Staff`, `Kitchen`, `Admin`).
* Fix backend setup (e.g. fixing `typescipt` typo in `backend/package.json` and structuring TypeScript config).

#### **Phase 2: Product Catalog & Atomic Inventory Ledger**
* Dynamic product creation with image uploads (Cloudinary / S3).
* Category management, variant support (e.g., 500g vs 1kg cake).
* Inventory ledger: atomic stock deductions and restock logs.

#### **Phase 3: Core Order Engine & Payment Integration**
* Unified order creation endpoint (handles both POS cash/UPI and online checkout).
* Order state machine (Controlled transitions: `PLACED` → `CONFIRMED` → `PREPARING` → `PACKED` → `OUT_FOR_DELIVERY` / `READY_FOR_PICKUP` → `DELIVERED` / `PICKED_UP`).
* Razorpay test checkout + Webhook verification.

#### **Phase 4: Frontend Storefront + High-Speed Cashier POS**
* **Customer Store**: Modern, appetizing bakery UI (menu, cart, delivery/pickup selection, live tracking timeline).
* **Staff POS**: Ultra-fast grid view, instant product search, quantity modifiers, cash/UPI toggle, printable thermal receipt view.

#### **Phase 5: Kitchen Display (KDS), Admin Analytics & Deployment**
* Kitchen screen: realtime/polled tickets showing pending items to prepare and pack.
* Admin dashboard: revenue, top-selling pastries, low-stock warnings.
* Production deployment (Render/Railway for backend, Vercel for frontend, MongoDB Atlas) + interview-ready README with architecture diagrams.
